# F03 implementation and verification record

## Implemented scope

The contracts and qualification-fixture packages share a versioned world/asset/media/identity/service boundary without selecting either renderer candidate. The original 55-entity courtyard includes four actual glTF resources, an animated skinned creature, movable props, four simultaneous calibrated corner tracks, a creature sound and an original wall-video marker. Nineteen generated files are checked for exact reproducibility.

The contract/reference tests cover document compatibility and hostile plain data, hierarchy and reference integrity, matrix/axis/handedness conversion, quaternion/listener behavior, distance attenuation and cutoff, immutable logical scenario replay, cancellation/disposal and rejection of stale or simulated qualification evidence. Fixture tests cover manifest and asset digests, the official glTF validator, animation/skin content and generator drift/symlink behavior. Workload and device files are target templates; they contain no measured capacity or claimed headset result.

## Integrated checks

F03's two additional test suites are explicit prerequisites of root `npm test`. CI's canonical example command now runs both public hosts. The separate tarball consumer covers core, contracts and qualification fixtures, including declarations, the exact fixture example and the shipped generator. Its generated dependency lock is checked against the root's pinned TypeBox version, public URL and integrity before the fresh install.

The standalone trace host must report `qualificationStatus: incomplete`: it exercises logical replay and content integrity, and cannot satisfy real-browser, real-service or physical-device requirements. This is an expected evidence distinction, not a skipped assertion.

The integrated local canonical run on 2026-10-17 passed all six required commands: install, check, both examples, independent consumer, sharding and dependency audit. It observed 39 package tests (1 core, 25 contracts and 13 fixtures) and 85 tooling tests, with zero failures or skips. All four actual glTF models passed the official validator without errors, warnings, informational messages or hints. The fresh external consumer passed with the root-pinned TypeBox dependency; the registry audit reported no advisories. This used Node v24.19.0 and npm 11.9.0. The local manifest remains explicitly local/incomplete and does not establish hosted acceptance.

The integrated source received a separate self security/code review after implementation and testing, covering bounded input handling, fixture-only authority, public packaging and the new CI coverage. The omitted F03 suite/consumer coverage identified during integration is corrected. No remaining blocking finding was identified in this scope. A formal review will bind these findings to the final PR commit. Hosted candidate identity, observed merge and main-branch results are recorded when they occur. At candidate review the progress state was implemented; the observed acceptance receipt below records completion. See [the qualification protocol](../qualification/f03.md), [review scope](../security/F03.md) and [CI procedure](../ci/README.md).

The Meshy repository secret remains unused.
