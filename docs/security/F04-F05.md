# Foundation evaluation integration review

This record covers the isolated evaluation packages and their CI integration. It is assistant self review, not independent human approval or production/hardware qualification. Candidate-specific review notes remain with each package.

## Actual boundaries

- The evaluation graphs remain outside the production engine workspaces. Exact upstream versions, source/file hashes, local adaptations and licenses are retained. Modern toolkit audits and unknown legacy upstream results are distinguished.
- CI uses unprivileged PR/main jobs, pinned actions, no provider secrets, no persisted checkout credentials and narrow retained artifacts. The aggregate requires both foundation and evaluation jobs; failures, cancellation or skipped work cannot become success.
- The evaluation evidence contract binds actual commands, run/attempt, head/base/tested source, tree, nested lockfiles, shared inputs and report bytes. Browser evidence must come from a fresh current-source run. Historical local captures and physical-device requirements retain their different status.
- Source checkout is restricted to pinned public repositories. Existing changed checkouts are rejected, not reset. Subprocesses use explicit configurations and credential-filtered environments. The source-only CI helper does not install/run Hubs/Spoke upstream dependencies or start services.
- Browser servers bind to loopback and restrict routes/requests to synthetic fixtures. The F05 import path has explicit evaluation-only data/allocation limits and rollback/disposal boundaries. Broader production import and worker isolation remain later asset-lane requirements.
