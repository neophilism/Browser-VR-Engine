# F03 self security and code review

Scope: shared contract validation, mathematical reference helpers, scenario execution, original fixture generation, local fixture ports, package exports and the standalone consumer. This is an assistant self review, not independent human approval. It does not mark F03 accepted, merged or production-qualified; F02 tooling and repository gates still apply when the change is integrated.

## Trust boundaries checked

- Documents are untrusted plain data. Fixed envelopes reject unknown fields and unsupported document versions. The pre-validation walk bounds depth, values, strings and parsed UTF-8 bytes, rejects nonfinite numbers and dangerous property names, and inspects descriptors without invoking getters. Non-enumerable state, cycles, sparse/extended arrays and nonplain objects fail. Executable JavaScript proxies are outside this plain-data API; it is not a code sandbox.
- World validation checks identifiers, parents, hierarchy cycles, finite/invertible transforms, required component support, built-in component versions, resource kinds, collider dimensions/mass, audio curves and consistent playback/source bindings across entities. Optional unknown component data is retained without execution. The host remains responsible for validating its registered extension versions and enforcing authorization.
- Qualification adapters are trusted executable evaluation code. The runner freezes cloned inputs, captures their digests, validates observations and disposes the supplied adapter even when validation, cancellation or candidate actions fail. The assessor prevents simulated, missing or stale records from satisfying incompatible assertions. Claimed evidence methods still require reviewed artifacts; this code cannot attest to physical hardware use.
- Local asset resolution is restricted to an explicit catalog with exact revision, size and digest checks; it returns copied bytes and has no remote or filesystem fallback. Fixture authorization is exact scoped matching with default deny, not production authentication. Serialized actor identifiers never establish an authenticated principal.
- The generator writes only its fixed package fixture directory, validates output containment and refuses symlink files/directories. CLI negative tests operate on disposable test packages and verify drift detection and an unchanged symlink target. This developer command is not a sandbox for a hostile process concurrently modifying the same filesystem; production worker isolation belongs to later asset cards.
- Runtime source imports contain no network calls, subprocess execution, provider SDK, application dependency or environment reads. CLI tests pass child processes only `PATH`; they explicitly fail on `child.error`, signals and unexpected exits. No provider credential, private source model or real recording is included or needed.

## Findings resolved during the separate review

Non-enumerable getters and sparse arrays with replacement properties could evade a keys-only JSON walk; the validator now checks all own names and array index shape. Canonical JSON rejects hidden/symbol state instead of silently hashing a reduced representation. Quaternion/matrix operations reject unrepresentable results. Playback IDs cannot ambiguously refer to different assets across entities. The scenario runner now owns disposal from entry, including invalid/pre-aborted inputs. The generator checks symlink destinations before reading/writing outputs. Regression checks cover these paths.

## Dependencies and verification boundary

`@sinclair/typebox` is pinned to `0.34.52` (MIT) as the one runtime validation dependency. `gltf-validator` is pinned to `2.0.0-dev.3.10` (Apache-2.0), used only by tests for the original synthetic models. Their exact package integrity records are in the lockfile; no installation scripts are required by F03. The source metadata links to [TypeBox](https://github.com/sinclairzx81/sinclair-typebox) and the [Khronos glTF Validator](https://github.com/KhronosGroup/glTF-Validator). F07 owns the broader foundation dependency/provenance gate.

Local verification covers the TypeScript build, negative static type assertions, named contract/math/scenario tests, fixture/CLI tests, byte regeneration, the four-model official validator, and the standalone consumer using installed package tarballs outside the workspace. Node child-process restrictions initially blocked CLI tests in the sandbox; the test correctly failed on `EPERM`. The scoped final local run permits those child processes with a minimal environment and no network/provider calls. Acceptance must use the current integrated commit and F02's required checks.

No browser rendering, actual physics simulation, live media services, conference capacity, physical audio or headset behavior is claimed by this F03 review. Those remain separate candidate and release evidence obligations.

## Integrated CI and installed-consumer review

The F02 root test script initially named only the core package. Integration now explicitly runs all three required package suites and both public example hosts; policy mutation checks reject removing the contracts/fixtures suites or substituting only the SDK example. The external consumer packs all three packages with explicit file inventories, verifies each tarball digest, checks the separately generated dependency lock against the root TypeBox pin before `npm ci`, and rejects workspace links, extra dependencies and substituted sources. It checks actual installed ESM paths and TypeBox resolution, the public fixture example, shipped generator and positive/negative declarations. Empty temporary user/global npm configs and an explicit public registry prevent reliance on ambient npm configuration; the environment allowlist and child-process failure checks remain.

The final integrated local canonical sequence passed all six commands, with 39 package and 85 tooling assertions, zero skipped/failed cases and no registry advisories. A separate root self review examined the contract implementation and the installed-consumer/CI changes after those tests. No material blocker remains in this reviewed scope. The formal GitHub review binds the final candidate SHA; this narrative is not an independent approval or physical/runtime qualification.
