# F02 — Separate self security review

## Scope and method

Reviewed the implemented workflow, dependency lock, workflow validator, evidence runner/verifier, package-boundary checks, source-exposure checks, progress validation, independent package consumer and test-shard mechanism after their local verification. A second agent assisted with a read-only review; this remains self review, not an independent human approval. The final PR receipt names the exact reviewed commit after it exists.

## Findings resolved before the final candidate

- Required command IDs now bind to canonical command vectors. Substituting a harmless command cannot satisfy retained evidence.
- Required job verification rejects missing or unrelated job sets, and the workflow always propagates prerequisite failure.
- The workflow validator requires the actual hosted runner, checkout, pinned toolchain and artifact steps in order. Removing or skipping them, or substituting local-preview mode, fails policy verification.
- The dependency audit retains its structured registry report. Process errors, missing data, contradictory results and registry failures cannot become a clean scan.
- Subprocesses inherit an allowlist of operational settings. Arbitrary provider keys and publishing credentials are excluded; synthetic-key tests verify the boundary without reading live credentials.
- Logs and structured reports redact recognized credentials without corrupting JSON. Source scanning reports locations and rule names rather than discovered values.
- Package-boundary validation checks dependency names and alias/file target values. Computed imports and hostile creator code remain outside this static check's stated scope.
- The shard check requires named test cases and demonstrates that a real failed assertion causes the runner and its affected shard to fail.

## Remaining scope limits

The committed workflow has minimal permissions, pinned action sources, no provider/deployment secrets, no privileged PR event and no credential-persisting checkout. Its policy checker is a regression control; an author able to change both policy and workflow is not isolated by that checker alone. Actual repository and credential access controls remain authoritative. The owner's existing Meshy repository secret is reserved for a future trusted integration workflow and is not consumed here.

No blocking finding remains in the reviewed foundation implementation. Hosted failure demonstration, final-candidate checks/review and merge verification are separate acceptance steps recorded in the PR and [F02 evidence](../evidence/F02.md). This review establishes no rendering, headset, service deployment or production security qualification.
